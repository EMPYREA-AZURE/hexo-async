Quick Start

部署hexo的命令行：

  • npm install hexo-cli -g //下载hexo命令行
  • hexo init blog //新建一个blog文件
  • cd blog //切换到blog文件夹
  • npm install //项目初始化
  • hexo server //hexo运行

下载hexo-theme主题的语句：

git clone -b master https://github.com/jerryc127/hexo-theme-butterfly.git themes/butterfly
//找到对应主题的下载命令

应用主题

修改 Hexo 根目录下的 _config.yml，把主题改为 butterfly

theme: butterfly

安装插件

如果你没有 pug 以及 stylus 的渲染器，请下载安装：
npm install hexo-renderer-pug hexo-renderer-stylus --save

新建文章命令：

新建一个文件命令：

hexo new name

在指定位置新建一个文件：

hexo new _posts name

上传GitHub命令：

1. 创建 GitHub 项目仓库

1.1 仓库命名与初始化

  • 必须注意：
    • 仓库名任意（如 my-blog），但 不要 使用 用户名.github.io。
    • 如果勾选 Initialize with a README，后续部署时需要先拉取仓库内容（避免冲突）。
  • 推荐操作：不勾选 README，直接创建空仓库。

1.2 仓库权限（公开或私有）

  • 注意：
    • 如果仓库设为 私有，GitHub Pages 功能需要付费（Pro 账户）。
    • 免费用户必须选择 公开仓库。

2. 配置 Hexo 部署设置

2.1 修改 _config.yml 的细节

  • 文件路径：Hexo 博客根目录下的 _config.yml。

  • 必须严格遵循的格式：

    yaml

    • 缩进：type、repo、branch 前必须有 两个空格，不能用 Tab。
    • 冒号后必须有空格：例如 repo: https://...（正确），repo:https://...（错误）。

2.2 分支名称选择

  • 推荐分支名：gh-pages（GitHub 默认识别此分支为 Pages 源）。
  • 若分支已存在：部署时会覆盖原有内容，确保分支无重要数据。

2.3 安装部署插件

  • 命令：

    bash

  • 常见问题：

    • 网络超时：切换 npm 镜像源：

      bash

    • 权限不足：在命令前加 sudo（仅限 macOS/Linux）。

3. 部署到 GitHub

3.1 执行部署命令

  • 完整流程：

    bash

  • 成功提示：

    • INFO Deploy done: git。
    • 检查 GitHub 仓库是否生成 gh-pages 分支。

3.2 处理身份验证问题 （第一次上传部署的时候，没有用到这个）

  • HTTPS 协议：

    • GitHub 已禁用密码验证，需使用 Personal Access Token (PAT)：
      1. 生成 PAT：GitHub → Settings → Developer Settings → Personal Access Tokens → 勾选 repo 权限。
      2. 部署时输入用户名 + PAT 代替密码。

  • SSH 协议（推荐）：

    • 生成 SSH 密钥：

      bash

    • 将公钥 ~/.ssh/id_ed25519.pub 内容粘贴到 GitHub → Settings → SSH and GPG keys。

    • 测试连接：

      bash

4. 设置 GitHub Pages

4.1 指定 Pages 源分支

  • 路径：仓库 → Settings → Pages → Build and deployment → Branch。
  • 必须选择：
    • Branch：gh-pages（或其他部署分支）。
    • Folder：/(根目录)。
  • 成功标志：
    • 页面顶部显示绿色提示：Your site is published at https://用户名.github.io/仓库名/。
    • 首次部署可能需要 1-2 分钟生效。

4.2 自定义域名（可选，第一次部署没有用到）

  • 步骤：

    1. 在 Pages 设置页输入域名（如 blog.example.com）。

    2. 在域名服务商添加 CNAME 记录：

      plaintext

    3. 在 Hexo 的 source 目录创建 CNAME 文件（无后缀），内容为域名。

  • 验证：

    • 访问域名，若显示博客内容即成功。
    • 若失败，检查 DNS 解析状态（可用工具：https://dnschecker.org）。./)

5. 验证部署结果

5.1 检查网站内容

  • 访问地址：https://用户名.github.io/仓库名/。

  • 常见问题：

    • 404 错误：

      • 确认仓库 Pages 分支和文件夹设置正确。
      • 确认 gh-pages 分支内有 index.html。

    • 样式丢失：

      • 修改 Hexo 的 _config.yml：

        yaml

      • 重新部署（返回3.1步骤）。

5.2 查看 GitHub 仓库文件

  • 检查点：
    • gh-pages 分支应有自动生成的静态文件（如 index.html, css, js 等）。
    • 若分支无文件，可能是部署命令未执行成功。

6. 后续更新博客

6.1 标准更新流程

bash

  • 强制推送（如果遇到冲突）：

    bash

6.2 更新后未生效

  • 可能原因：
    • 浏览器缓存：按 Ctrl + F5 强制刷新。
    • GitHub Pages 构建延迟：等待 1-2 分钟。

7. 终极故障排除

7.1 部署失败（ERROR Deployer not found: git）

  • 原因：未安装 hexo-deployer-git。

  • 解决：

    bash

7.2 提示 Permission denied (publickey)

  • 原因：SSH 密钥未正确配置。

  • 解决：

    bash

7.3 部署后只有 README.md

  • 原因：未正确生成静态文件。

  • 解决：

    bash

总结

  • 每一步的核心检查点：
    1. Git 和 Node.js 安装验证。
    2. _config.yml 格式是否正确。
    3. GitHub 仓库分支与 Pages 设置是否匹配。
    4. 部署命令是否包含 hexo clean。
    5. 身份认证方式（SSH 或 PAT）。
  • 最终成功标志：通过 https://用户名.github.io/仓库名/ 访问到完整博客。

如果遇到问题，请随时提供完整的 命令行报错截图 或 页面显示效果，我会帮你分析！
